### Chemins d'appel suivis

1. Meta : `POST /webhook/meta` → `webhookJsonParser` (corps brut) → contrôle présence signature → `processBatch` → `parseMetaWebhook` (pur) → `routeMessage` → `findRoute(display_phone_number)` → contrôle du transport de l'agent IA → `authenticatedTransport` (`getTransportForBot` → résolveur agent IA puis organisation → `verifyWebhookSignature` sur les octets reçus) → contrôle `phone_number_id` → `serveMessage` → `checkServable` (statut agent IA en cache, statut organisation en base) → âge → réservation `numéro:identifiant` → verrou `numéro|contact` → `processLocked` (relecture du routage et du statut, session, accueil, `handleMessage`, extraction de lead, `events.publishLead` → `CrmBridge`).
2. CM.com : `POST /webhook/cm-com/:clientId/:botId/:secret` → `findBot` (cache) → `isAuthorized` (secret de l'enregistrement de l'agent IA seulement, comparaison à temps constant, transport `cm-com`) → analyseur JSON → `parseCmWebhook` → numéro destinataire dans la liste de l'agent IA de l'URL → `getTransportForBot` → `serveMessage` (même suite).
3. Administration : `requireAuth` → `createRequireOrganization` (`resolveAccess`, organisation relue en base) → `requireAction` → services appelés avec `activeClientId(req)` uniquement ; écritures `upsertBot` → `upsertBotRecord` / `setBotNumbers` → `invalidateTransports` → réindexation du cache.

## 4. Observations héritées, hors périmètre

- Hérité, hors périmètre : file LLM globale `pLimit(10)` partagée par toutes les organisations dans `src/core/handler.ts:13` ; une organisation très sollicitée retarde les autres (voisin bruyant). L'équité par organisation de `client-fairness.ts` ne couvre que le mode plateforme.
- Hérité, hors périmètre : `events.getRecentMessages` (`src/core/events.ts:51-56`) garde en mémoire les 100 derniers messages de toutes les organisations et les rend sans filtre par défaut. Aucun appelant aujourd'hui ; à supprimer avant qu'un écran ne l'utilise.
- Hérité, hors périmètre : `phone_number_id` saisi sans contrôle de format puis inséré dans le chemin des URL Graph (`src/transport/meta-cloud.ts:249`, `536`). Avec ses propres jetons seulement, donc sans croisement ; à restreindre aux chiffres.
- Hérité, hors périmètre : résolveur LLM qui bascule sur la clé de la plateforme quand un enregistrement `byo` n'a pas de clé (`resolver.ts:56-64`) et ignore `bot.llm.mode` (déjà au §7 de l'audit).
- Hérité, hors périmètre : jeton de vérification GET Meta global, donc connu de toutes les organisations qui configurent leur app ; sans effet sur les messages (il ne prouve que l'abonnement). Prévu par compte en 2b-2.
- Hérité, hors périmètre : `CrmBridge` câblé au démarrage seulement (audit 5.11) ; il aggrave I-2, puisque le repli HubSpot se déclenche au redémarrage suivant sans action visible.
- Hérité, hors périmètre : secret d'URL CM.com sans rotation possible ; deux `PUT /transport` simultanés peuvent générer deux secrets, l'URL affichée au premier devenant invalide (même organisation).
- Hérité, hors périmètre : un agent IA actif dont les identifiants manquent voit ses messages écartés avec un simple journal, sans compteur ni état visible au back-office.
